# شات بوت صوتي (Voice Assistant) — Google Gemini API

مشروع صفحة ويب تتعرف على صوت المستخدم، ترسل النص إلى نموذج **Google Gemini**
عبر خادم PHP خلفي، ثم تنطق الرد بالصوت. المشروع جزء من مهمة عملية هدفها:
رفع الملفات على سيرفر، إصلاح ملف الـ PHP المسؤول عن الاتصال، والتوثيق على GitHub.

## هيكل المشروع

```
├── index.html          # واجهة الدردشة (مربع المحادثة + زر الميكروفون)
├── style.css           # تنسيق الواجهة
├── app.js              # التعرف على الصوت (STT) + استدعاء الخادم + النطق (TTS)
├── .gitignore          # يمنع رفع الملف الذي يحتوي المفتاح السرّي
└── api/
    ├── assistant.php         # الخادم الخلفي: يستقبل النص ويستدعي Gemini API
    ├── config.php        # يحتوي مفتاح Gemini الحقيقي (لا يُرفع على GitHub)
    ├── config.sample.php # نسخة نموذجية فارغة من الإعدادات (تُرفع على GitHub)
    └── .htaccess          # يمنع فتح config.php مباشرة من المتصفح
```

## 1) المشكلة التي تم إيجادها في كود PHP

عند فحص المشروع الأصلي، كانت الواجهة الأمامية (`app.js`) تستدعي المسار
التالي عند كل رسالة صوتية:

```js
const BACKEND_URL = "api/assistant.php";
fetch(BACKEND_URL, { method: "POST", ... })
```

لكن عند فحص محتويات المشروع، **لم يكن ملف `api/assistant.php` موجودًا إطلاقًا**
داخل المجلد المرفوع. أي أن الواجهة كانت تحاول الاتصال بمسار غير موجود على
الخادم، فيرجع السيرفر خطأ `404 Not Found`. بما أن الاستجابة لم تكن ناجحة
(`res.ok` تساوي false) ولا بصيغة JSON صالحة، كان الكود في `app.js` يدخل
كتلة `catch` ويعرض الرسالة:

> "حدث خطأ أثناء الاتصال بالخادم. حاول مجددًا."

بمعنى آخر: **المشكلة لم تكن خطأ منطقيًا داخل ملف PHP، بل غياب الملف
بالكامل**، وهو ما يفسر فشل كل محاولة اتصال بدون استثناء.

## 2) كيف تم حل المشكلة

تم إنشاء ملف `api/assistant.php` من الصفر ليقوم بالمهام التالية:

1. التأكد أن الطلب من نوع `POST` فقط (وإلا يرجع خطأ 405).
2. قراءة الجسم الخام القادم من `fetch()` بصيغة JSON واستخراج حقل `prompt`.
3. التحقق من وجود `prompt` وأنه غير فارغ (وإلا خطأ 400).
4. تحميل مفتاح Gemini السرّي من ملف منفصل `config.php` (بدل كتابته
   مباشرة داخل `assistant.php`، حماية للمفتاح واتساقًا مع نصيحة الأمان
   الواردة في المادة التدريبية: "لا تكشف مفتاح الـ API").
5. إرسال طلب `POST` إلى Gemini REST API عبر `cURL`:
   `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent`
6. معالجة جميع حالات الفشل المحتملة (فشل الاتصال، رد خطأ من Gemini،
   عدم وجود نص في الرد) وإرجاع رسالة JSON واضحة مع كود HTTP مناسب.
7. عند النجاح، إرجاع الرد بنفس الشكل الذي يتوقعه `app.js`:
   ```json
   { "reply": "نص رد Gemini هنا" }
   ```

كما تمت إضافة:
- `api/config.sample.php`: نسخة فارغة يستنسخها أي مطور آخر ليضع مفتاحه الخاص.
- `api/.htaccess`: يمنع أي زائر من فتح `config.php` مباشرة عبر الرابط.
- `.gitignore`: يستثني `api/config.php` الحقيقي من الرفع على GitHub حتى
  لا يتسرب المفتاح السرّي.

## 2.1) مشكلة إضافية اكتُشفت أثناء الرفع الفعلي على InfinityFree

بعد رفع الملفات فعليًا على استضافة InfinityFree، ظهر خطأ **403 Forbidden**
عند محاولة الوصول إلى `api/assistant.php` (وليس خطأ من كود PHP نفسه). بالرجوع
إلى الدليل الرسمي لـ InfinityFree
([توثيق أخطاء 403](https://forum.infinityfree.com/t/redirected-to-infinityfree-403-forbidden-page/58664))
تبيّن أن الاستضافة تحظر تلقائيًا **أي رابط يحتوي كلمة "chat"** لمنع
سكربتات الدردشة المباشرة (Live Chat) التي ترهق السيرفر بالتحديث المستمر
— ومثالهم الحرفي في التوثيق هو **`chat.php`** بالضبط.

**الحل:** تمت إعادة تسمية الملف من `api/chat.php` إلى `api/assistant.php`،
وتحديث `BACKEND_URL` داخل `app.js` ليطابق الاسم الجديد. بعد إعادة التسمية
اختفى خطأ 403 لأن الرابط لم يعد يحتوي الكلمة المحظورة.

## 2.2) مشكلة إضافية اكتُشفت أثناء الاختبار على XAMPP محليًا

بعد اختبار المشروع محليًا عبر XAMPP، وصل رد فعلي من خادم Google لكنه
كان رسالة خطأ: **"النموذج models/gemini-2.0-flash لم يعد متاحًا"**.
هذا يؤكد أن الاتصال والمفتاح والكود كلها تعمل بشكل صحيح — المشكلة
فقط أن Google أوقفت نموذج `gemini-2.0-flash` القديم.

**الحل:** تحديث اسم النموذج داخل `api/assistant.php` من
`gemini-2.0-flash` إلى **`gemini-3.5-flash`** (النموذج المستقر الحالي
حسب توثيق Google الرسمي). واجهة `generateContent` نفسها لم تتغير،
فقط اسم النموذج.

## 3) خطوات رفع الملفات على السيرفر

### أ) على سيرفر محلي (XAMPP)

1. تشغيل XAMPP وتفعيل خدمة **Apache**.
2. نسخ مجلد المشروع بالكامل إلى: `C:\xampp\htdocs\voice-chatbot`
   (أو `/opt/lampp/htdocs/voice-chatbot` على لينكس).
3. الدخول إلى `api/config.php` ووضع مفتاح Gemini الحقيقي بدل
   `ضع_مفتاحك_هنا` (المفتاح يُستخرج مجانًا من
   `https://aistudio.google.com/app/apikey`).
4. فتح المتصفح على: `http://localhost/voice-chatbot/index.html`
5. الضغط على زر الميكروفون واختبار المحادثة.

### ب) على استضافة خارجية (مثل InfinityFree أو أي استضافة تدعم PHP)

1. الدخول إلى لوحة التحكم (cPanel) → **File Manager** أو الاتصال عبر **FTP**.
2. رفع جميع الملفات والمجلدات (`index.html`, `style.css`, `app.js`,
   ومجلد `api/` بالكامل) داخل مجلد الموقع (عادة `htdocs` أو `public_html`).
3. التأكد أن الاستضافة تدعم PHP و`cURL` (مفعّلة افتراضيًا في أغلب
   الاستضافات المجانية مثل InfinityFree).
4. تعديل `api/config.php` مباشرة على السيرفر (عبر File Manager أو FTP)
   ووضع المفتاح الحقيقي فيه.
5. فتح رابط الموقع في المتصفح واختبار الميكروفون.

> **ملاحظة أمان:** المسار `BACKEND_URL = "api/assistant.php"` في `app.js` هو
> مسار نسبي، لذلك يعمل تلقائيًا بغض النظر عن اسم النطاق (domain) الذي
> تستضيف عليه الموقع، بدون الحاجة لتعديل الكود.

## 4) رفع المشروع على GitHub

```bash
# 1. الدخول لمجلد المشروع
cd voice-chatbot

# 2. تهيئة مستودع Git
git init

# 3. إضافة جميع الملفات (config.php الحقيقي مستثنى تلقائيًا بفضل .gitignore)
git add .

# 4. أول Commit
git commit -m "Fix: add missing api/assistant.php backend to connect frontend with Gemini API"

# 5. ربط المستودع المحلي بمستودع GitHub (بعد إنشائه من الموقع)
git remote add origin https://github.com/USERNAME/voice-chatbot.git

# 6. رفع الملفات
git branch -M main
git push -u origin main
```

بعد الرفع، تأكد أن `api/config.php` **غير موجود** داخل المستودع على
GitHub (يجب أن يظهر فقط `config.sample.php`) — وهذا يؤكد أن المفتاح
السرّي لم يتسرب للعامة.

## 5) ملخص التدفق الكامل بعد الإصلاح

```
🎤 المستخدم يضغط الميكروفون
   ↓ (Web Speech API)
📝 تحويل الصوت إلى نص داخل المتصفح
   ↓ fetch("api/assistant.php")
📡 app.js يرسل النص إلى الخادم
   ↓
🐘 api/assistant.php يقرأ المفتاح من config.php ويستدعي Gemini API
   ↓
✨ Gemini يرجع نص الرد
   ↓ JSON: { "reply": "..." }
🔊 app.js يستقبل الرد وينطقه عبر Speech Synthesis API
```

بهذا التعديل، أصبح الاتصال بين الواجهة والخادم يعمل بشكل صحيح، واختفت
رسالة الخطأ "حدث خطأ أثناء الاتصال بالخادم".
